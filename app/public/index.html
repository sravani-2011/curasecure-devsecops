Security controls inside the application

The app follows the OWASP Top 10 and healthcare privacy principles (confidentiality, integrity, availability, minimum necessary access).

ID

Authentication

bcrypt-hashed passwords and 30-minute JWT sessions in HttpOnly, SameSite=Strict cookies. Accounts lock after 5 failed attempts, and login is rate-limited.

RB

Role-based access

Doctors see full records and write notes. Nurses see clinical data with masked identifiers. Admins see no clinical data, only audit and operations.

AE

Encryption at rest

PHI fields (national ID, phone, address, diagnosis, notes) are stored as AES-256-GCM ciphertext. The key lives in a Kubernetes Secret, never in code.

AU

Tamper-evident audit

Every record view, change, denied access and login is logged in a SHA-256 hash chain, so altering past entries is detectable.

IV

Input validation

Strict allow-list validation, 10 KB request limit, output escaping, and no stack traces leaked to clients.

HD

Security headers

Strict Content-Security-Policy (no inline scripts, no third-party content), frame-ancestors none, no-referrer, Permissions-Policy, and CSRF origin checks.

Hardened platform

The platform is locked down too, not just the code.

Non-root, read-only container

Runs as UID 1000 with a read-only root filesystem, all Linux capabilities dropped and no privilege escalation.

Pod Security "restricted"

The namespace enforces the strictest Kubernetes Pod Security Standard, with a RuntimeDefault seccomp profile.

Network policies

Default-deny ingress and egress. The pods may only receive traffic on port 3000 and cannot call out.

Secrets management

Encryption key, JWT key and demo password are generated per cluster and stored in a Kubernetes Secret, and they never appear in logs.
